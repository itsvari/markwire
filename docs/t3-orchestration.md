# Run grading in T3 Code

Choose T3 orchestration in setup and configure a provider instance ID and model ID for every grader alias, the arbiter and the sanity reviewer. The local run preferences also hold role permissions, report preferences and any linked machine IDs. Open the prepared grading workspace in T3. Ask an operator agent to run the workflow below and give it a run ID. For a targeted run, give it the affected submission IDs or point it at the prepared revision and its impact plan.

```text
Run the grading workflow for this prepared workspace using docs/t3-orchestration.md.
Use run ID demo-round. Follow the configured grader, arbiter and sanity model choices.
Wait for delegated work and validate its outputs. Pause for decisions I need to make.
```

## Start or resume the run

1. Run `python grading_orchestration.py start RUN`. Add `--submission ID` once per target for a subset. Use `python grading_orchestration.py status RUN` to resume. The journal lives in `private/orchestration/` and belongs to the operator agent. Keep a single operator for a run and use a single run per overlapping set of grading records.
2. Read the configured role settings. Discover `orchestrator_capabilities` once before the first delegate, as required by T3. Use only the configured available model, options and provider. Surface an unavailable selection or permission conflict to the TA. Validate and name the tool that will provide delegating and computer-use capabilities when the role requires them.
3. Register any known remote evidence probes using the procedure below. At setup and after each stage, run `python grading.py stage-report --stage STAGE --if-requested`. Add `--blocked` when a problem prevents progress. For a guide that needs synthesis, give its `--draft` findings to the [curator workflow](ongoing-grading.md#return-decisions-from-a-stage-guide). Resolve blockers affecting a dependent stage even when reports are disabled. The validated grading records establish whether scores, coverage and verification are complete.

## Dispatch and advance

1. Read `status RUN`. Reserve each available slot with `python grading_orchestration.py reserve RUN SLOT`. Write journal updates sequentially and launch the reserved independent grader slots in parallel. A reservation lists missing submission IDs, an attempt number and the proposed `clientRequestId`, `mode` and `target` fields for `delegate_task`. Pass only those three fields and the appropriate task brief to T3. Use a stable request ID if transport fails and T3 permits retry in the same provider session.
2. For local grading slots, generate the current role prompt with `python grading.py prompt --role ROLE --submission ID` for each listed target. Add `--grader ALIAS` for an independent grader. Use a local shared T3 delegate for a prepared workspace and give it the absolute workspace path, the generated prompts, and its exact write paths. A policy-isolated grading installation should provide a standalone input and output view per alias. A T3 worktree sees committed files, so local ignored snapshots and inputs must be provisioned separately if using one. Save complete evaluations as each submission finishes. Direct graders to their configured evidence scope and prohibit review of peer marks until arbitration.
3. Immediately record the returned handles using `python grading_orchestration.py attach RUN SLOT --request-id REQUEST --task-id TASK --thread-id THREAD --link 'LINK'`. Use the reserved `clientRequestId` for `REQUEST` and keep T3’s returned link verbatim. For a reservation left behind before the handles were saved, reconcile the original dispatch before creating another attempt. A request key is only a retry key within the provider session that accepted it.
4. Follow T3’s returned `next` action and wait for completion signals. A child can finish a turn while its own workers are still running. When the result is available and delegated work has settled, check the expected role output files and run `python grading_orchestration.py finish RUN SLOT --request-id REQUEST --status completed`. Record `--executed-model` when T3 exposes it. The journal validates the scoped outputs, including the current verdict digest for sanity. If a completed delegate left missing outputs, record it as `failed` so the incomplete scope can be retried. Keep partial evidence and completed records.
5. A question or approval pauses the affected work. Surface it with the child thread link and resume after the operator supplies a decision or approval. For failure, cancellation or interruption, use the corresponding terminal status with `finish`. Request a new attempt with `reserve RUN SLOT --retry` after the original attempt settles. The journal supplies a new request ID and only outstanding submissions. Reconcile a quota or access problem before retrying, and use a new operator-confirmed run configuration when the configured model must change.
6. Dispatch arbitration after the configured independent slots and any required coverage checks are complete, then dispatch sanity against the current verdict. The runner checks per-submission artefacts, and prompt generation applies the same role gates as the manual workflow. At `human_review`, surface any unresolved submissions and the release guide if selected. Human approval and export use the existing grading commands.

## Run a check on a linked machine

1. Use the portable bundle format to make a task spec for one submission. Include the capabilities the worker will need, such as `browser`, `desktop` or a named course fixture. The role preferences must permit the requested browser or desktop use. Register the probe before its dependent stage starts. The remote worker can run while an earlier stage is in progress.

   ```text
   python grading_orchestration.py add-probe RUN --spec probe.json --machine MACHINE --model-role grader_A --before arbitration
   ```

2. Find a linked machine with `t3_environment_links`. Confirm the linked environment ID, reachability and access match the run configuration. Preflight its requested provider and model with the capabilities tool when T3 permits it. Confirm the chosen transfer channel is available. Apply the reserve output’s `model_role` permissions in the worker brief and keep authentication on the target machine.
3. When the `probe-TASK_ID-ATTEMPT` slot is available, reserve it. Run `python grading.py bundle pack probe.json probe.zip` and use the configured file transfer to stage the archive. If the reservation has `dispatch: t3`, `delegate_task` can launch the assigned agent with the linked `target.environmentId`. Give the agent the staged archive path and the result destination. Follow the same `attach`, completion and recovery steps as for a local delegate.
4. On the target machine, run `python grading_bundles.py open probe.zip task-workspace` and follow the generated `TASK.md` in that standalone workspace. Return the output of `python grading_bundles.py finish task-workspace result.zip` through the same transfer channel. On the main machine, run `python grading.py bundle import result.zip` before recording the delegate completed. Share the resulting evidence path with the dependent stage. Inspect blocked observations and application state before releasing dependent work. Attribute the imported observations to their collector and independently validate any returned assessment against the main workspace’s active scope and template. Independent graders still carry out checks required by their verification policy.

A reservation with `dispatch: manual` uses the same pack, open, finish and import steps. The operator imports the result directly and records the attempt completed using its request ID. For an imported probe that needs more work, register a new bundle attempt before dispatching the dependent stage.
