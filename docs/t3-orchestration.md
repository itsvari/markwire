# Run grading in T3 Code

Choose `t3` orchestration during setup and configure a provider instance ID and model ID for every grader alias, the arbiter, and the sanity reviewer. `private/run-preferences.json` also stores role permissions, stage report preferences, and any linked machine definitions. Open the prepared assignment workspace in T3 Code and ask an operator agent to follow this runbook with a chosen run ID. For a targeted run, specify the affected submission IDs or point the operator at the revision workspace and its impact plan.

```text
Run the grading workflow for this prepared workspace using docs/t3-orchestration.md.
Use run ID demo-round. Follow the configured grader, arbiter and sanity model choices.
Wait for delegated work and validate its outputs. Pause for decisions I need to make.
```

## Start or resume the run

1. Run `python grading_orchestration.py start RUN`, adding `--submission ID` once per target to restrict scope. Use `python grading_orchestration.py status RUN` to resume an existing run. The orchestration journal lives in `private/orchestration/` and belongs solely to the operator agent. Keep one operator per run and never run overlapping orchestration runs against the same grading records.
2. Read the configured role settings in `private/run-preferences.json`. Call `orchestrator_capabilities` once before the first delegation, as required by T3 Code. Use only the configured provider, model, and options; surface any unavailable selection or permission conflict to the TA rather than substituting another model. Confirm which tool provides delegation, browser, or desktop capabilities when a role requires them.
3. Register any known remote evidence probes using the procedure below. At setup and after each stage, run `python grading.py stage-report --stage STAGE --if-requested` (adding `--blocked` when a problem halts progress). If a stage report needs synthesis, pass its `--draft` JSON through the [curation and decision workflow](ongoing-grading.md#return-decisions-from-a-stage-report). When a stage report has open findings with options, pause for the TA to answer every open finding across all topics (using **Defer** where offered or providing custom instructions) and import the single complete JSON packet via `import-decisions`. Resolve blockers affecting a dependent stage even when stage reports are disabled. Validated grading records determine whether evaluations, coverage, and verification are complete.

## Dispatch and advance

1. Check `python grading_orchestration.py status RUN`. Reserve each available slot with `python grading_orchestration.py reserve RUN SLOT`. Write journal updates sequentially, then launch reserved independent grader slots in parallel. Each reservation outputs the pending submission IDs, attempt number, and exact `clientRequestId`, `mode`, and `target` fields for `delegate_task`. Pass only those fields plus the role brief to T3 Code. Reuse the same `clientRequestId` only when retrying a failed transport call within the same provider session.
2. For local grading slots, generate the current role prompt with `python grading.py prompt --role ROLE --submission ID` for each listed target (adding `--grader ALIAS` for an independent grader). Use a local shared T3 delegate for a prepared workspace and supply the absolute workspace path, generated prompts, and exact output write paths. If course policy requires filesystem isolation, provision a separate input/output copy per alias. Note that a T3 git worktree includes only committed files, so ignored snapshots and inputs must be provisioned separately if using one. Instruct graders to save each submission's evaluation as soon as it finishes, keep within their configured evidence scope, and avoid reading peer evaluations before arbitration.
3. Immediately record the returned handles with `python grading_orchestration.py attach RUN SLOT --request-id REQUEST --task-id TASK --thread-id THREAD --link 'LINK'`, passing the reserved `clientRequestId` as `REQUEST` and preserving T3's returned link verbatim. If a reservation exists without attached handles, reconcile the original dispatch before creating a new attempt.
4. Follow T3's returned `next` guidance and wait for completion signals; a child turn may finish while its own sub-tasks are still settling. Once the final result is available and delegated work has settled, verify the expected output files and run `python grading_orchestration.py finish RUN SLOT --request-id REQUEST --status completed`, adding `--executed-model` when T3 reports it. The runner validates all scoped outputs (including the current verdict digest for sanity review). If a completed delegate left outputs missing, record it as `failed` so only the remaining submissions are retried; preserve completed records and evidence.
5. A user question or approval request pauses the affected work. Surface it to the TA alongside the child thread link and resume once answered. For failed, cancelled, or interrupted delegates, record the matching terminal status with `finish`. After the original attempt settles, request a new attempt with `reserve RUN SLOT --retry`; the runner issues a fresh `clientRequestId` scoped strictly to outstanding submissions. Resolve quota or access errors before retrying, and obtain operator confirmation before changing a configured model.
6. Dispatch arbitration once all configured independent grader slots and required coverage checks are complete, then dispatch sanity review against the current effective verdicts. Both the orchestration runner and `prompt` enforce the same stage gates as the manual workflow. At `human_review`, surface any unresolved submissions and the release stage report if configured. Human approval and grade export always remain with the TA via the standard CLI commands.

## Run a check on a linked machine

1. Create a portable task specification JSON for one submission, declaring required capabilities such as `browser`, `desktop`, or a named course fixture. The assigned role's preferences must permit any requested browser or desktop access. Register the probe before its gated stage starts; the remote worker may run concurrently with an earlier stage.

   ```text
   python grading_orchestration.py add-probe RUN --spec probe.json --machine MACHINE --model-role grader_A --before arbitration
   ```

2. Inspect linked machines with `t3_environment_links` and confirm that the environment ID, reachability, and access level match `private/run-preferences.json`. Preflight the requested provider and model via `orchestrator_capabilities` where T3 supports it, and confirm the file transfer channel is ready. Apply the reserved `model_role` permissions in the remote worker brief and keep all authentication local to the target machine.
3. When the `probe-TASK_ID-ATTEMPT` slot is available, reserve it. Run `python grading.py bundle pack probe.json probe.zip` and stage the archive over the configured transfer channel. If the reservation reports `dispatch: t3`, launch the worker with `delegate_task` using the linked `target.environmentId`, passing the staged archive path and result destination, then follow the standard `attach`, completion, and recovery steps.
4. On the target machine, run `python grading_bundles.py open probe.zip task-workspace` and follow the generated `TASK.md`. Package results with `python grading_bundles.py finish task-workspace result.zip` and transfer `result.zip` back. On the main machine, run `python grading.py bundle import result.zip` before marking the delegate `completed`. Share the imported evidence path with the dependent stage, inspect blocked observations and application state before advancing, attribute imported observations to their collector, and independently validate any returned assessment against the active workspace template. Independent graders must still complete all checks required by their verification policy.

A reservation with `dispatch: manual` uses the same `pack`, `open`, `finish`, and `import` steps: the operator imports the returned archive directly and marks the attempt `completed` with its reserved `request_id`. If an imported probe requires further work, register a new attempt number before dispatching the dependent stage.
